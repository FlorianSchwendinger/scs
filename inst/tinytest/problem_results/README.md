## Saved Results from the SCS 3.3.1 Test Suite

Each `.RDS` file holds one solve from the C test suite bundled with SCS
3.3.1 (`src/scs/test/problems/*.h`): the problem data (`A`, `P`, `b`,
`obj`), the cone, the full settings list, an `initial` warm start when
the test supplied one. The `upstream` element records the originating test function,
the call number within it, SCS's exit flag and, for generated problems,
`planted`: `c'x*` and `b'y*` of the solution the generator planted.

The files were generated by compiling the upstream test functions
against the SCS 3.3.1 library built with this package's flags and R's
own BLAS/LAPACK, running them inside an R process, and recording every
`scs()` / `scs_solve()` call. Doubles are transferred as hexadecimal
floats so the saved data are the bytes SCS saw. Cases that cannot be
expressed through the R API are not included: re-solves on a reused
workspace (`scs_update()`), problems whose matrix dimensions upstream
deliberately corrupts, settings structs that are left unset, and a call
that only writes the problem to a data file (upstream asserts nothing on
it).

`test_problems.R` replays every file through `scs()` and applies the
assertions upstream makes for that solve: the exit flag, the objective
against upstream's known optimum, and its `verify_solution_correct()`,
with upstream's tolerances. These hold on every platform; the solution
itself is not stored, because the iterates depend on the platform's
floating-point arithmetic.
